# AI Engineering Workbench 0.1.1

`0.1.1` is a remediation release for the local-first MVP.

## Included

- Hermetic `doctor` tests that no longer require GitHub CLI to be installed on
  minimal test machines.
- `py.typed` packaging marker so downstream type checkers can inspect the
  `workbench` package.
- Git and adapter edge fixes for dotted GitHub repository names, worktree
  operation timeouts, remote branch collisions, and unresolved agent commands.
- Write-time secret redaction for validation evidence.
- Supervised agent process lifecycle with exit-code capture, PID reuse checks,
  process-group termination, and in-place nullable schema upgrades.
- Hardened dashboard API error handling with shared process-lifetime database
  engine setup and proper HTTP status codes.
- CLI entrypoint/context separation and command-surface snapshot coverage.
- Validation run grouping and portfolio pass-rate metrics based on grouped
  check executions instead of raw command rows.
- Threat-model and README truth sync, including deferred sandboxed validation
  documentation.
- Dashboard API/client/component decomposition with focused frontend tests.

## Validation

The release-readiness baseline is:

```text
uv run ruff check src tests apps/api scripts
uv run mypy src
uv run pytest
uv run bandit -q -r src scripts
cd apps/dashboard && npm run lint && npm run typecheck && npm test && npm run build
```

## Known Limits

- Validation commands still execute on the host until the deferred sandboxed
  validation runner is implemented.
- Live GitHub PR creation is not exercised in automated tests; tests use fake
  local `gh` and `git` tools.
- Dashboard tests use the existing Vitest and React server-rendering setup; no
  new frontend test dependencies were added.
